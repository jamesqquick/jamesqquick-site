# Scaffold the Astro Project

## Outcome

You will create a new Astro project named `weekender`, install its dependencies with pnpm, and verify both development and production builds. The starting project will use TypeScript in strict mode and target Astro 7.

## Check the runtime

This course requires Node.js 22.12 or newer and pnpm 11 or newer. Confirm both tools before creating the project:

```sh
node --version
pnpm --version
```

If either version is older, update it before continuing. Using the course runtime avoids debugging differences caused by the package manager or Node.js rather than your code.

## Create the project

Run Astro's project creator from the directory that should contain the new `weekender` folder:

```sh
pnpm create astro@latest weekender
```

Choose the minimal starter, install dependencies, and use strict TypeScript. Whether you initialize Git during the prompt does not change the application code.

Move into the project:

```sh
cd weekender
```

The generated package versions depend on when you run the command. This course eventually targets Astro 7.2, React 19.2, and Tailwind CSS 4.3. The following is the eventual target configuration, not the dependency state for this lesson:

```json
{
  "dependencies": {
    "@astrojs/react": "^6.0.5",
    "@tailwindcss/vite": "^4.3.3",
    "astro": "^7.2.10",
    "react": "^19.2.8",
    "react-dom": "^19.2.8",
    "sharp": "^0.35.4",
    "tailwindcss": "^4.3.3"
  }
}
```

Do not add React and Tailwind yet. The focused integration lesson will make those changes and explain the configuration. For now, check that your generated `astro` dependency has major version 7. If it does not, align it explicitly:

```sh
pnpm add astro@^7.2.10
```

The caret range keeps the project on Astro 7 while allowing compatible minor and patch releases.

## Use the course TypeScript settings

Replace the generated `tsconfig.json` only if it differs from this configuration:

```json
{
  "extends": "astro/tsconfigs/strict",
  "include": [".astro/types.d.ts", "**/*"],
  "exclude": ["dist"],
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "react"
  }
}
```

The strict Astro preset gives TypeScript enough information to catch invalid props and unsafe values. The JSX options prepare the project for React components that you will add later. Keeping them here makes the intended framework boundary explicit from the beginning.

The `.astro/types.d.ts` file is generated by Astro. Do not edit it by hand. The `dist` directory contains build output, so TypeScript excludes it from source checking.

## Understand the initial scripts

Astro's starter creates the main development scripts. Make sure `package.json` keeps these commands:

```json
{
  "scripts": {
    "dev": "astro dev",
    "build": "astro build",
    "preview": "astro preview",
    "astro": "astro",
    "check": "astro check"
  }
}
```

`dev` starts a server with source updates. `build` generates the production output. `preview` serves that output locally. `astro` gives direct access to the CLI, and `check` runs Astro and TypeScript diagnostics.

Install the checker and TypeScript before using that script:

```sh
pnpm add -D @astrojs/check@^0.9.10 typescript@^6.0.3
```

If the starter did not create the `check` script, add it now. Then run `pnpm check` once to establish a clean diagnostics baseline.

The course adds formatting, linting, unit testing, and browser testing later. Do not add every future dependency to the scaffold. Adding tools when they become relevant makes each configuration change easier to explain and verify.

## Run the development server

Start Astro:

```sh
pnpm dev
```

Open `http://localhost:4321`. You should see the minimal starter page. Edit the heading in `src/pages/index.astro` and save. The browser should update without a manual restart.

Stop the server with Ctrl+C when you are ready to test the build.

## Verify the production build

Run:

```sh
pnpm build
```

Astro should generate a `dist/` directory. Then serve it:

```sh
pnpm preview
```

Open the preview URL and confirm the starter page still works. Development mode can hide assumptions that fail during generation, so checking a production build early creates a useful baseline.

## Checkpoint

Your project should now meet these conditions:

- The folder is named `weekender`.
- `package.json` uses Astro 7.
- `tsconfig.json` extends `astro/tsconfigs/strict`.
- `pnpm check` completes without diagnostics.
- `pnpm dev` serves the project.
- `pnpm build` creates `dist/` without errors.

## Exercise

Open `package.json` and explain why the project uses scripts instead of invoking binaries from `node_modules` directly. Then run `pnpm exec astro --version` and compare that version with the declared Astro range. This confirms which installed binary the scripts will execute.
